候选 A / B 文献碰撞审查
核验日期：2026-11-05
用途：立项筛选与实验设计；以下“剩余假设”是待验证研究命题，不是已经成立的新颖性或实验结果。

结论
优先保留 A 的收窄版本：严格总内存预算下，按后续任务操作能否区分来保留状态与事件差异。单独的有限记忆、事件记忆、变化感知、状态更新、证据保留、来源追踪、定向重放均已被直接覆盖，不能作为新贡献。
B 降为备选：竞争答案假设、信息增益取证、充分性核验、缺失证据驱动搜索、三态停止、答案稳定性与风险校准停止均已有近邻工作。需要超出这些组合的明确技术差异后再投入。
“严格总预算”也不是 A 的独占点：MemEvo 已报告 bounded memory 和本地 payload 稳定。因此 A 应比较同等预算下任务相关状态差异的保留效果，不能仅改用字节计量就宣称创新。

候选 A：可检验的收窄假设

建议问题表述：在不可无限保留或重放历史、未来查询未知的流式任务中，相比按视觉新颖性/语义重要性/实体摘要选择记忆，显式保护“会改变后续合法操作或答案的状态差异”，是否能在同等总存储与推理成本下更好地保留事件顺序、状态更改和撤销关系？

这里的可区分性应落成可执行测试。例如两段历史外观和主题相似，但“先开后关”与“先关后开”的当前状态不同；一次计划、一次成功执行、一次执行失败可能描述同一目标，却支持不同下一步操作。只看全局 embedding 相似度会混淆，但是否能系统改善需要实测。任务状态抽象和充分统计量是既有原则，不能把原则本身当新理论。

可测假设 A1：在保持相同骨干、同样观测频率、同等存储字节和读入 token 的条件下，保护操作可区分差异提高成对历史辨别率、当前状态有效率和状态迁移顺序准确率，尤其在高相似帧、重复动作、撤销与长延迟查询条件下。该提升应超过增加标签、实体图或普通 change-aware 记录所得提升。
可测假设 A2：同样字节预算下，任务操作区分损失比视觉重建/语义相似度更能预测下游错误；由该损失选择淘汰对象会改善任务成功率—总存储曲线。若只改善自定义代理指标而不改善真实任务，不能宣称有效。
可测假设 A3：在查询类别于测试前固定、具体测试问题不可见的条件下，优势能迁移到未见事件组合与更长干扰序列。不能让 memory writer 偷看当前或未来测试 query，也不能用测试集挑存储规则。

最小可行验证
1. 先建立带可执行状态机或可核验标注的成对历史集：事件顺序翻转、短暂变更后恢复、同物体不同身份、成功/失败操作、撤销与冲突。用这些控制样例定位差异，再上自然视频/交互任务；不要只造有利于本法的合成集。
2. 以 MemEvo、FOLIO、DeltaStreamer 的可获得实现为主要流式基线；GEM 与 MoM 作为状态/证据机制参照。若实现不可得，明确“重实现”并保留作者设置，不能只用不完整弱化版本。
3. 同时给两个协议：严格流式、不许历史回放；预算内回放、所有存留帧/视频字节计入。原始视频、视觉 embedding、文本、图节点、索引、指针、缓存和可恢复的归档都要计量，公共冻结骨干权重单列。读入 token、预处理与检索延时、视觉调用次数另报。
4. 至少扫描三个真实存储预算，并保持每个比较同一 reader/backbone。报告成功率、成对辨别、当前状态错误、事件顺序/次数错误、预算违例率、实际字节峰值。使用成对 bootstrap 或预先指定检验呈现不确定性；不能把不同模型/不同 replay 权限的分数当同条件优势。
5. 关键消融：去操作可区分损失；换成语义重要性；换成视觉变化量；只留当前状态不留变更来源；同等字节随机/近期淘汰；冻结 reader 后只换记忆机制。若优势完全来自多存帧、更多调用或更强 reader，该主张被证伪。

立项门槛
A 只有在真实预算相同下，能稳定纠正现有强基线对“外观相似但操作后果不同”的系统性混淆，且机制消融支持因果作用，才值得继续。当前文献只支持把它作为待测差异，尚不能说已有证据证明新颖或优越。

候选 B：仅保留备选问题
可以测“固定主动取证策略下，独立校准的序列级停止规则是否以更少视觉成本满足指定的错误早停风险”，并区分缺证据、已取证但推理错、预算耗尽三类结局。但这只是邻近方法的组合起点；BEACON、REVEAL、TRACE、CLOSER 与 Conformal Thinking 必须同时对照。
错误早停应定义为：停止时输出错误，而在同一个允许预算内存在尚未获得、能纠正答案的证据；可用预先固定的充分证据 oracle 协议作诊断，不能把 test-time oracle 提供给模型。还应单报正确但证据未覆盖、无解仍继续与预算退出。
如采用 conformal 或集中不等式，需要预先冻结候选策略/阈值集合，校准与测试按视频/场景而非相邻帧拆分，并处理从多候选规则选最省成本者的选择效应。普通 split conformal 的静态覆盖并不自动推出任意自适应取证与多次检查下的停止保证。
如果剩余工作只有改 prompt、增加 rubric、稳定性再问一次或给 BEACON 附加阈值，就不建议作为主线。
