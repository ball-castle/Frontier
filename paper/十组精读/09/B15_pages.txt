        1  Introduction

               Scientific discovery often involves proposing hypotheses, evaluation, and using the resulting evidence
              to guide further investigation [2, 3]. Advances in reasoning, coding, and agentic tool-use capabilities
               of large language models (LLMs) have enabled systems that automate part of this discovery process
                  [4, 5]. In the iterative discovery loop, a failed attempt can reveal an implementation constraint, while a

successful modification can suggest an idea worth applying elsewhere. A key design question is how to
learn from this accumulated experience to improve subsequent search efficiently.

Recent test-time training (TTT) frameworks, such as TTT-Discover [1] and ThetaEvolve [6], provide a
promising solution to this challenge by combining iterative search with test-time reinforcement learning
(RL) [7, 8]. Specifically, an LLM generates candidate solutions and receives evaluation feedback. These
evaluated attempts provide training data for RL, which internalizes search experience in model weights
to guide subsequent generation. Their results demonstrate that TTT is a powerful test-time adaptation
method on challenging scientific discovery tasks, enabling smaller open-weight models to outperform
inference-only systems based on frontier models, such as AlphaEvolve [4]. However, TTT requires
online model weight adaptation during the whole discovery process, which is usually computationally
expensive and time-consuming (see Table 3). It makes TTT hard to scale to larger models for more
complex discovery tasks. This motivates us to explore: under the same discovery framework, is there a
more efficient test-time adaptation method that can achieve comparable or even better performance than
test-time training?

We hypothesize that evolving external memory could be a efficient alternative to online weight updates for
scientific discovery. Our core intuition is that current LLMs already have broad foundational knowledge,
reasoning and coding capabilities to use experience accumulated during discovery. Continually distilling
and organizing this experience in external memory may therefore be sufficient to improve subsequent
discovery, without internalizing it through weight updates. Building on this intuition, we introduce
Test-Time Memory Evolution (TTME), a plug-and-play self-evolving memory system for scientific
discovery. We update the memory from evaluation feedback and provide relevant content in the context
to guide the subsequent steps.

Specifically, we divide the search experience into two components: practical lessons for implementing
candidate solutions and algorithmic ideas for improving task scores. Correspondingly, TTME maintains
two complementary memory modules: Guideline Memory and Strategy Memory. Guideline Memory
distills execution and evaluation feedback into shared operational guidelines for reliable implementa-
tion. Strategy Memory extracts effective algorithmic ideas from score-improving modifications and
consolidates related experiences into reusable strategies. We select and adapt relevant strategies to
guide subsequent exploration, combining ideas from different search attempts.

Our contributions are summarized as follows:

 • We investigate whether a test-time memory evolution can outperform test-time weight updates in
   scientific discovery, and introduce an plug-and-play self-evolving memory method that continually
   updates external memory from evaluated search experience to guide subsequent discovery with a
   fixed-weight model.

 • We evaluate TTME under two TTT frameworks across five mathematical construction tasks and three
   models spanning 8B and 120B parameters. We preserve each framework’s experimental configuration,
   replacing only its TTT part with TTME. TTME outperforms the reported TTT results in all evaluated
   tasks. Our analysis shows that TTME reduces running time by 47.7 −58.4% and computational
   costs by 82.8 −84.6% relative to TTT. These results demonstrate that TTME is a more efficient
   alternative to TTT for scientific discovery.

 • We analyze the search behavior of TTME and TTT during the discovery. Both methods improve the
   implementation validity rate relative to the underlying discovery framework without TTT or TTME,
   but TTME achieves better performance. Moreover, compared with TTT, TTME more frequently
   builds on score-improving combinations of previously explored ideas.

2  Related Work

Non-Parametric Adaptation.  Non-parametric discovery methods use fixed-weight LLMs to generate
executable candidates and guide subsequent search with evaluation feedback [9, 10, 5, 11–13]. The
effectiveness of this process depends on how search policies interact with the operators used to generate
and modify candidates [14, 15]. FunSearch [9] and AlphaEvolve [4, 16] evolve candidate programs
through repeated generation and evaluation with proprietary LLMs. Adaptive search methods further



                                            2

use observed progress to adjust exploration intensity and allocate computation across candidate
populations [17]. These studies establish search organization as an important factor in the quality and
efficiency of automated discovery. Beyond selecting promising candidates, execution experience can also
help subsequent exploration [18–24]. [25] and [26] compare candidate solutions and their evaluation
results to identify promising modifications. [27] uses execution feedback to guide which optimizations
to attempt next by adding, reprioritizing, or pruning proposed modifications in a search tree. These
studies improve discovery through the joint design of search, planning, and feedback utilization. We
instead study experience accumulation specifically as a modular adaptation mechanism and introduce
TTME, a plug-and-play memory system for existing discovery frameworks.


Parametric Adaptation.  Parametric methods update the LLMs through RL on evaluated search
attempts [28–30]. ThetaEvolve [6] turns evolutionary program search into a dynamic RL environment.
As its program archive evolves, training proceeds from newly discovered candidates rather than
repeatedly starting from the same initial program. TTT-Discover [1] designs both its learning objective
and search rule around finding a single high-quality solution rather than maximizing average performance.
It exponentially upweights high-reward attempts during training and uses the best observed outcomes
to prioritize states for further search. These methods internalize search experience in model weights,
enabling open-weight models to surpass results achieved with proprietary models [6, 1]. However,
continually updating model weights during discovery incurs additional computational cost. We show that
evolving external memory offers a more effective and efficient alternative to online weight adaptation.
TTME achieves better discovery outcomes within both frameworks, and our efficiency experiments
demonstrate lower computational cost.

3  Method

3.1  Background and Problem Formulation

We study scientific discovery as an iterative process of proposing hypotheses, evaluating them, and using
the resulting evidence to guide subsequent proposals. We focus on tasks with executable candidate
programs and a task-specific verifier, where a program produces a construction whose validity and
objective value are assessed by the verifier.

Let v(x) ∈{0, 1} indicate whether candidate program x produces a valid result, and let s(x) denote
its evaluated score, oriented so that larger values are better. For the set Xeval of candidates evaluated
within the search budget, the best valid score is

                            s⋆= max s(x).                                         (1)
                                                     x∈Xeval
                                                  v(x)=1

Our goal is to find the highest-scoring valid candidate within a given search budget.

Our study builds on two existing TTT scientific discovery frameworks, TTT-Discover [1] and ThetaE-
volve [6]. We describe two frameworks using a common formulation. Each framework maintains an
archive of search states, each representing a candidate solution and its associated records. At each
search step, the framework selects states from the archive as parents for new attempts. The code
associated with a selected parent is its parent program. Given the task specification, parent program,
and associated records, the LLM generates candidate programs. We execute and evaluate these pro-
grams, recording their validity, scores, and execution feedback. The framework then updates the archive
for subsequent search. We preserve each framework’s original parent-selection and archive-update
rules.

Both frameworks use search feedback to update model weights through test-time RL. We ask whether
non-parametric methods, e.g., memory adaptation, can substitute for these parametric methods, e.g.,
online weight adaptation. Writing Dt for evaluated search records available to an update, we contrast
two adaptation mechanisms:

                   Weight adaptation:  θt+1 ←URL(θt, Dt),

Evaluated search attempts provide practical lessons for implementing candidate solutions and algorithmic
ideas for improving task scores. We organize this experience into two complementary memories,
Mt = (Lt, St). Guideline Memory Lt stores shared guidelines for implementing candidate solutions.
Strategy Memory St organizes algorithmic ideas into reusable strategies that we select and adapt to
guide subsequent search.

3.2  Guideline Memory: Shared Operational Lessons

Execution and evaluation feedback can reveal implementation problems and choices that improve task
scores. Lessons from one attempt can guide the implementation of later candidates. We distill these
observations into compact guidelines stored in Lt. Each guideline specifies when it applies, explains the
relevant failure or improvement, and recommends a concrete action.

Every K search steps, we form a summary rt of outcomes collected across parents since the previous
update, including valid results, their scores, and observed failures. We update the memory in two
stages, first proposing guidelines Gt and then incorporating them into the existing memory:

                        Gt ←Distill(rt, Lt),    Lt+1 ←Maintain(Lt, Gt, t).                       (3)

Here, Distill prompts the same base model with rt and the existing guidelines Lt to propose Gt. In
Maintain, we match each proposal against existing entries. For a match, we increment the entry’s
recurrence count and refresh its last reaffirmed step to t; otherwise, we add a new entry. We remove
stale entries and enforce a capacity limit, prioritizing recurrence counts and breaking ties by recency.
The retained guidelines provide shared context for implementing subsequent candidate solutions.

3.3  Strategy Memory: Reusable Algorithmic Experience

Combining existing ideas is important in scientific discovery. An idea behind a score-improving
modification may also be useful for other candidates. Strategy Memory preserves these ideas and how

they were applied, so they can be adapted and combined in subsequent searches.

We update Strategy Memory every K search steps, together with Guideline Memory. We select
evaluated cases where a modified program produces a valid result with a higher score than its parent,
and denote this collection by D+t . For each case, we analyze the original and modified programs, their
differences, and the evaluation results using the same base model. The model extracts one or more
experience notes from each case, each describing an algorithmic idea, how it was applied, and its source
case. We denote the resulting collection of notes by Et.

Different modifications can implement the same algorithmic idea in different ways. We group experience
notes that share an underlying idea into a strategy family and maintain a persistent strategy entry for
each family. Each entry describes the shared idea, its application conditions, and the different ways it
has been implemented, with references to the source cases. The extraction of experience notes and the
update of Strategy Memory are expressed as:

                           Et ←Extract(D+t ),     St+1 ←Consolidate(St, Et).                       (4)

Here, Extract denotes the case-wise extraction described above. In Consolidate, we use the same base
model to compare new notes with existing entries and assign them to existing or new families. For an
existing family, the model combines the new notes with the current entry to update its content. For a
new family, the model creates an entry from its notes.

3.4  Strategy-Guided Search and Candidate Generation

With two memories established, we now describe how they guide new candidate generation. Guideline
Memory provides shared guidance for implementation. Strategy Memory contains ideas drawn from
specific modifications, which may need adaptation before they can be applied to another parent. We
therefore propose Strategy-Guided Search to select relevant strategies and turn them into parent-specific
modification instructions. When no suitable strategy is selected, we use the parent context and Strategy
Memory to propose a new idea and formulate its modification instruction.
Specifically, at search step t, let p(t)i  denote the program associated with the i-th selected parent. Let
C(t)i  denote the input context supplied by the underlying framework for the i-th parent at step t, such
as task specification and parent program p(t)i  .

For each parent, we use a selector (base model) to analyze and select up to N distinct strategies from
Strategy Memory based on their potential to improve the parent program. The selector is provided
with the parent context, a summary of each strategy entry, and the strategies already assigned to earlier
parents in the current step. Selection proceeds sequentially across parents:

                            a(t)i = Select C(t)i   , ˆSt, A(t)<i  ,      a(t)i = (a(t)i,1, . . . , a(t)i,N),                      (5)

Here, ˆSt denotes the summaries of strategy entries. We collect the nonempty strategy selections for
earlier parents into
                          A(t)<i = na(t)j,n  1 ≤j < i, 1 ≤n ≤N, a(t)j,n ̸= ∅o .

Each nonempty a(t)i,n denotes a selected strategy.  If fewer than N strategies are selected, we set the
remaining elements of a(t)i  to ∅. The selector prioritizes improvement potential for the current parent.
Among similarly plausible choices, it prefers a strategy not yet included in A(t)<i.
Then, we produce a parent-specific modification instruction d(t)i,n for n = 1, . . . , N:

For a selected strategy, one adaptor (base model) reads its full entry and the full parent code, then
specifies how to apply the strategy to that parent. When a(t)i,n = ∅, the adaptor uses the parent and
available strategy memory content to propose a new idea.

We use the constructed instructions to guide candidate generation. Adapting an explored strategy
allows us to combine an idea extracted from a score-improving modification with the parent program’s
existing approach. Moreover, to explore additional ideas that may improve the task score, we also
generate candidates without a modification instruction.

Specifically, let B denote the total candidate budget per parent. Both generation branches receive the
parent context C(t)i  and Guideline Memory Lt. We generate αB candidates through Direct Generation
using this shared context, where α denotes the fraction of the budget allocated to this branch. We set
α = 1/2 in our experiments. For Strategy-Guided Generation, we additionally supply a modification
instruction d(t)i,n and generate (1 −α)B/N candidates for each of the N instructions:

                            x ←Generate(C(t)i   , Lt),                                        (7)
                            x ←Generate(C(t)i   , Lt, d(t)i,n).                                   (8)

The candidates’ evaluation outcomes inform subsequent memory updates, which provide guidance for
later search steps. The complete procedure is summarized in Algorithm 1. Implementation details and
prompts appear in Appendices C and D.

4.2  Main Results

Performance across frameworks and models. TTME outperforms both TTT and search without
TTT across two discovery frameworks, three models, and five tasks (Tables 1 and 2). The comparison
with TTT shows that evolving external memory can yield better discovery results than existing weight-
update methods. The comparison with search without TTT shows the benefit of adding memory to
the underlying fixed-weight search procedure. Together, these results establish TTME as an effective
alternative to test-time weight adaptation across the evaluated settings. Appendix E visualizes the
discovered constructions.


Progress during search. We next examine how TTME improves the best-found score over the
course of search (Figure 3). Under the TTT-Discover framework, TTME surpasses the TTT scores
within 25 steps across all three tasks and both models. Under the ThetaEvolve framework, TTME also
surpasses the TTT scores on three tasks. These trajectories show that TTME can improve on the final
TTT results before exhausting the search budget.

4.3  Ablation Studies

Combining TTME with TTT.  Having established the effectiveness of TTME with fixed model
weights, we examine whether adding TTT further improves performance. We compare four settings
under the TTT-Discover framework with Qwen3-8B: neither TTT nor TTME, TTT alone, TTME
alone, and their combination (Table 4). In the combined setting, the RL-updated model performs both
candidate generation and memory-related operations. TTME alone achieves the best scores on AC2
and Erdős, while adding TTT worsens both results. This comparison further supports using TTME as
an alternative to TTT rather than requiring both forms of adaptation.

5  Conclusion

We investigate whether evolving external memory can outperform test-time training for scientific
discovery within the same discovery frameworks. We introduce TTME, which distills search experience
into operational lessons and algorithmic strategies to guide a fixed-weight model. Across two frameworks,
three models, and five mathematical tasks, TTME achieves better scores than TTT in every evaluated
setting. Under TTT-Discover with Qwen3-8B, it reduces runtime excluding evaluation by 47.7–58.4%
and FLOPs by 82.8–84.6%, including all memory-related calls. These results establish self-evolving
memory as an effective and computationally efficient alternative to test-time weight updates for the
discovery tasks we study.

C.2  Memory Updates

We update both memories every K = 2 search steps using outcomes collected since the previous
update.


Guideline Memory.

   1. Summarize recent outcomes. The outcome summary covers recent attempts across parents,
      including valid results, their scores, and execution or validity failures.

   2. Distill guidelines. The same fixed-weight base model reads the outcome summary and current
      guidelines, then proposes up to three lessons per update, at most one for failure avoidance. Each
      lesson specifies a trigger, explains the mechanism, and gives a concrete action. The parser extracts
      the lesson text from the response.

   3. Match and merge. For each proposed lesson, we compute its Jaccard similarity to stored
      guidelines using lowercased word-token sets. A similarity of at least 0.5 counts as a match: we
      retain the stored text, increment its recurrence count, and refresh its last reaffirmed step. An
     unmatched lesson enters memory with count one and the current step.

   4. Remove stale entries and enforce capacity. Guidelines expire when more than 20 search
      steps have passed since their last reaffirmation. Among the remaining entries, we retain at most
      24, ranked by recurrence count with recency breaking ties.

   5. Include guidelines in generation prompts. Both Direct Generation and Strategy-Guided
     Generation receive the retained guidelines as shared context. Each prompt displays up to 240
      characters per guideline; memory stores the full lesson text.

Strategy Memory.

   1. Select valid improvement cases. We select evaluated parent–child pairs in which the child
      passes the task verifier and improves on its parent. Both scores must be finite; improvement
      follows the task’s objective direction, consistent with s(child) > s(parent) in Section 3.3.

   2. Extract experience notes. The same fixed-weight base model reads the parent and child
     programs, their code diff, and evaluation results.  It writes an experience note describing the
      algorithmic idea behind the change and its application conditions. Each note retains a reference
      to its source case; a change containing independent ideas can yield separate notes.

   3. Group notes into strategy families. The model compares new notes with existing strategy
      entries and groups notes that share an underlying algorithmic idea into the same family. It creates
     a new family for a distinct idea and preserves implementation differences as variants within each
      family.

   4. Consolidate and store strategy entries. For each family receiving new notes, the model
     combines those notes with the previous entry, if one exists, to update the description of the shared
      idea, application conditions, and implementation variants. We store the entry, its summary, and
     the supporting notes with source references. Families without new notes retain their existing
      entries.
